# セーブ（続きから）

ホストの端末に部屋の進行を1枠だけ保存し、「続きから」で再開できるようにする仕組み。

## 形

- セーブを持つのは**ホストだけ**。参加者は何も保存しない。
- 保存するのは**部屋の進行**（誰が参加していたかは条件にしない）。
  そのため、**1人で続きを始めても、友達を呼んで始めても**同じ続きから遊べる。
- 枠は1つ。進むたびに上書きする（オートセーブ）。手動セーブは無い。

## ファイル

```
%USERPROFILE%/AppData/LocalLow/<会社名>/Roomies/roomies_save.json
```

`SaveSystem.FilePath` が場所を持つ。Unityからは `Roomies/Save/Open Save Folder` で開ける。
書き込みは一時ファイル→置き換えなので、保存中に落ちても前のセーブは壊れない。

上書きのたびに、ひとつ前のセーブを `roomies_save.json.bak` に残す。
本体が読めないとき（壊れた・手で編集して失敗した）は、この控えから読む。
控えも読めなければ「セーブ無し」として扱い、「はじめから」だけになる（落ちない）。

Steam Cloud（Auto-Cloud）に載せるときは、このフォルダの `roomies_save.json` を対象にする
（Steamworks 側の設定はまだしていない）。

## 保存される内容

| 項目 | 備考 |
|---|---|
| Day・朝/夜・残り秒 | 残り秒はそのターンの途中から再開するため |
| 共同口座の残高 | |
| 次回家賃への上乗せ額 | 夜イベントで積み上がった分 |
| 置いてある家具 | カタログ番号と位置・向き・効果が効いているか |
| 冷蔵庫 | 食材が入っているか・壊れているか |
| 参加者の所持金 | **名前で**覚える。同じ名前の人が入ってきたら戻す |

保存**しない**もの：誰が参加していたか、持っていた物、配達や密輸の途中経過、
その日だけの状態（今日のおねがいの進み具合、招き猫をなでたか、ブレーカー、寝ているか）。

**負けたらセーブを消す。** 家賃を払えずゲームオーバーになった時点でセーブを消すので、
「負ける直前」から何度もやり直すことはできない。次に遊ぶときは「はじめから」になる。
ゲームオーバー画面の「もう一度」でやり直した場合は、そこからまた保存が始まる。
この挙動は `RunSaveManager` の `Delete Save On Game Over` で切れる。

## 流れ

1. メインメニューでセーブがあると「続きから」ボタンが出る（`MainMenuManager`）
2. 押すと `SaveSystem.PendingLoad` に読み込んだデータが入り、そのままホストを作る
3. GameRoomの `RunSaveManager` がそれを部屋へ反映し、`PendingLoad` を空にする
4. 以後、進行が変わるたびに `RunSaveManager` が上書き保存する
   （日・朝夜・口座・家賃の上乗せ・家具の増減や置き直し・冷蔵庫・所持金のどれかが変わったとき。
   朝↔夜の切り替え演出の最中は書かない）
5. 「ホスト」（はじめから）を押したときは `PendingLoad` を空にするので、新しい部屋になる
   （セーブファイルは消さない。次のオートセーブで上書きされる）。
   続きがあるときは押し間違いで進行を失わないよう、1回目は確認文を出すだけで、
   もう一度押すと始まる（文と秒数は `MainMenuManager` のインスペクター）
6. ホストがポーズ画面から「メニューへ」「終了」を選ぶと、確認を出す時点と抜ける直前に
   `RunSaveManager.TrySaveNow()` で保存する。確認文はホストだけ
   「全員のゲームが終了します（進行は保存されています）」になる
   （負けた後など保存が残らないときは「保存されません」。文は `EscMenuUI` のインスペクター）。
   ウィンドウを直接閉じたときも `OnApplicationQuit` で保存を試みる

## 置いてある物

| どこ | 何 | 置き直す |
|---|---|---|
| GameRoom | `RunSaveManager` | `Roomies/Save/Build Save Manager` |
| MainMenuSteam | `Canvas/MainMenuPanel/ContinueButton` | `Roomies/Save/Build Continue Button` |

ボタンは `HostButton` を複製して作るので見た目はそろう。位置・大きさ・文字は
シーンビューとインスペクターで自由に直してよい（作り直しても既にあれば動かさない）。

保存の間隔や、所持金を戻すかどうかは `RunSaveManager` のインスペクターで変えられる。

## テスト用

- `Roomies/Save/Delete Save File` … セーブを消す（確認ダイアログあり）
- `Roomies/Save/Open Save Folder` … 置き場所をエクスプローラーで開く

## 増やすとき

`RoomiesSaveData` に項目を足したら `RoomiesSaveData.CurrentVersion` を上げる。

読み込めるのは `MinSupportedVersion`〜`CurrentVersion` の版だけ。
- 足した項目が「無ければ既定値」で困らないなら、`MinSupportedVersion` はそのままにする
  （古いセーブもそのまま続きから遊べる。版1→2 はこの形）
- 古いセーブをそのまま読むと壊れる変更をしたときだけ `MinSupportedVersion` も上げる
  （それより古いセーブは使われなくなる）
- 自分より新しい版のセーブは読まない（新しいゲームで保存した物を古いゲームで開いた場合）

## テスト

`Assets/Tests/Editor/RoomiesSaveTests.cs`（EditMode）。置き場所を一時フォルダへ向けて動くので、
本物のセーブには触らない。読み書き・壊れたファイル・版の違い・控えからの復旧・
部屋の状態（日数・口座・家賃の上乗せ・冷蔵庫・家具）の往復を見ている。
